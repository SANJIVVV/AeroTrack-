Chapter 1: Project Overview

AeroTrack Pro is an enterprise-grade full-stack airport baggage tracking, auditing, and anomaly monitoring platform designed for modern aviation operations. The application tracks passenger luggage through physical checkpoints—from initial check-in through security screening, aircraft ramp loading, in-flight transit, arrival ramp processing, reclaim belts, and passenger collection.

Unlike conventional systems that expose black-box estimates or predictable linear baggage tags, AeroTrack Pro introduces Cryptographically Secure Random Number Generation (CSPRNG) with unbiased rejection sampling for luggage reference tags, strict state-machine journey validations, transparent rules-based anomaly detection, and an explainable delay-risk estimation framework.

Chapter 2: Problem Statement

Airport ground operations face severe challenges in luggage handling:

  • Passenger Uncertainty: Passengers face complete information blackouts once luggage enters conveyor holds, resulting in high support burdens and flight anxieties.
  • Predictable Luggage Identifiers: Baggage IDs generated via naive counters or pseudo-random modulo formulas suffer from predictable modulo bias, creating vulnerabilities where luggage references can be guessed or spoofed.
  • Undetected Screening Bottlenecks: When luggage stalls at security screening or sorting rings, ground handlers typically discover delays only after flight departure.
  • Opaque Risk Scoring: Ground handlers are reluctant to act on automated delay warnings when machine-learning systems provide no transparent justification.

Chapter 3: Project Objectives

  • Build a secure, collision-resistant baggage tag generation engine using cryptographic entropy and unbiased rejection sampling.
  • Implement a deterministic journey state machine that enforces forward progress and alerts when mandatory checkpoints (such as hold-baggage screening) are bypassed.
  • Deliver optical camera-based QR code scanning with idempotency safeguards preventing duplicate scan logs.
  • Design an explainable delay-risk scoring module that decomposes operational factors (dwell time, flight delays, missed scans) for human review.
  • Establish role-based portals for Passengers, Ground Handlers, and Airport Administrators.

Chapter 7: Module-by-Module Functionality

The 8-Stage Baggage Journey State Machine

Luggage follows a strictly validated linear progression defined in shared-utils/src/status.js:

REGISTERED -> CHECKED_IN -> SECURITY_SCREENING -> LOADED -> IN_TRANSIT -> ARRIVED -> ON_BELT -> COLLECTED
  • Forward Skips: Moving from CHECKED_IN directly to LOADED is permitted operationally (to avoid blocking luggage physically), but immediately flags a high-severity MISSING_CHECKPOINT anomaly because mandatory security screening was missed.
  • Backward Moves: Attempting to regress luggage status (e.g. LOADED $\to$ CHECKED_IN) is rejected with INVALID_SEQUENCE.
  • Exception States: DELAYED, MISSING, and INCIDENT_REPORTED can be entered from any active stage and exited by resuming the main flow.

Chapter 13: Authentication, Session Management & RBAC

AeroTrack Pro avoids stateless JWT vulnerabilities by implementing secure server-side sessions:

  • Password Security: Hashed using `bcryptjs` with 12 salt rounds. Dummy hashes mitigate user enumeration timing attacks.
  • 6-Digit OTP Challenges: Stored hashed in `OtpChallenge`. Challenges expire in 5 minutes with a 60-second request cooldown.
  • Session Storage: Stored in MongoDB `sessions` collection with crypto-random tokens sent in `HttpOnly`, `SameSite=lax` cookies.
  • Role-Based Access Control: Supported roles: `passenger`, `staff`, and `admin`. Admin actions require `requireRole('admin')`.

Chapter 15: Important Algorithms & Formulations

CSPRNG Unbiased Rejection Sampling

Standard modulo generation introduces modulo bias when range $M$ does not divide $2^{32}$. AeroTrack Pro's rejection sampling algorithm in shared-utils/src/qr.js:

Mathematical Formulation
1. Range size $M = 1,000,000$. Max 32-bit unsigned integer $2^{32} = 4,294,967,296$.
2. Rejection limit: $\text{limit} = 2^{32} - (2^{32} \pmod M) = 4,294,000,000$.
3. Sample $n \sim \text{Uint32}$ from crypto.getRandomValues.
4. If $n \ge \text{limit}$, reject and resample.
5. If $n < \text{limit}$, return $n \pmod M$. Every remainder has uniform probability $P = 10^{-6}$. Rejection probability is only $0.0225\%$.

Chapter 17: Delay-Risk Prediction Engine

Extracts a 9-dimensional operational vector at prediction time:

[stageIndex, minutesSinceLastScan, dwellRatio, skippedCheckpoints, openAnomalies, flightDelayed, flightCancelled, minutesToDeparture, notLoadedNearDeparture]
  • Rules Baseline Heuristic: Additive formula starting at 0.05 base risk. Dwell time contributes up to +0.40, skipped checkpoints +0.25, departure proximity without loading +0.30. Bounded strictly in $[0.05, 1.0]$.
  • Explainability Factor Breakdown: Each factor contributing $>0$ is displayed in the UI with an plain-English explanation.
  • Logistic Regression ML Fallback: If delay_model.json is provided, computes logistic log-odds $z = \beta_0 + \sum \beta_i x_i$ and sigmoid probability $\hat{P} = \frac{1}{1 + e^{-z}}$.

Chapter 25: Master Viva Questions & Answers (40+ Questions)

Part 1: Basic & Architectural Foundations

1. What is AeroTrack Pro, and what is its primary academic purpose?
AeroTrack Pro is a full-stack Web Application Development (WAD) project for airport baggage tracking that combines cryptographically secure QR tags, physical checkpoint verification, automated anomaly detection, and explainable delay-risk prediction.
2. What problem does AeroTrack Pro solve in airport logistics?
It eliminates passenger anxiety by providing transparent scan timelines, prevents duplicate or skipped checkpoint scans, and gives ground handlers automated warnings when luggage misses security screening or stalls at transit stations.
3. Why does the system explicitly avoid claiming continuous GPS tracking?
Real-world airport baggage handling relies on optical barcode/RFID checkpoints. Luggage does not contain active GPS satellite transmitters. Claiming continuous GPS tracking between checkpoints would be technologically inaccurate.
4. What is the role of the shared-utils workspace?
It provides a single source of truth for business logic—journey state machines, rejection sampling RNG, QR format parsers, and anomaly rules—reused by both the frontend client and the backend server.

Part 2: Frontend Engineering

5. Why is the frontend built with vanilla HTML/CSS/JS without React or Vue?
It eliminates complex build-tool dependencies, prevents bundler version rot, provides instant cold load times, and allows faculty to inspect the clean code directly in the browser DevTools.
6. How is client-side routing implemented?
In `frontend/js/lib/router.js` using the HTML5 History API (`pushState` and `popstate`), intercepting internal link clicks to render dynamic views without triggering full-page browser reloads.
7. How does the camera barcode scanner function?
It uses the `html5-qrcode` library to access the device's video stream via `navigator.mediaDevices.getUserMedia`, decodes optical QR patterns in real time, and sends the extracted reference to the API.
8. How are dark and light themes managed?
`frontend/js/theme-init.js` runs synchronously in the HTML `` before the DOM renders, applying the user's saved theme from localStorage to avoid any flash of unstyled content.

Part 3: Backend & Express Architecture

9. Why Express 5 over Express 4?
Express 5 natively handles rejected Promises in asynchronous route handlers, eliminating the need to wrap every route in boilerplate `try/catch` or custom async-wrapper helpers.
10. How does the middleware pipeline process requests?
Helmet sets security headers $\to$ CORS validates origins $\to$ Rate limiters check quotas $\to$ Body parser reads JSON $\to$ Cookie parser extracts session tokens $\to$ CSRF middleware confirms headers $\to$ Session loader attaches the user $\to$ Route controllers execute.
11. How are background anomaly sweeps executed?
`backend/src/index.js` sets a 5-minute `setInterval` calling `runAnomalySweep()`, which queries MongoDB for active bags that have exceeded their station dwell thresholds.
12. How does the server shut down gracefully?
Signal listeners for `SIGINT` and `SIGTERM` stop the HTTP listener, clear background intervals, close MongoDB connections, and terminate cleanly.

Part 4: MongoDB Atlas & Persistence

13. Why use MongoDB Atlas instead of MySQL?
Luggage tracking involves polymorphic audit events, nested scan findings, and variable flight manifests, which map naturally to flexible JSON documents without rigid join overhead.
14. What are Mongoose schemas and models?
Schemas define document structure, data types, validators, and default values. Models are compiled constructors that provide the interface for executing MongoDB CRUD operations.
15. How are database credentials protected?
Stored exclusively in `.env`, loaded via Zod validation, and passed through `redactMongoUri()` which strips passwords from all application logs and error messages.
16. How does optimistic locking work in baggage updates?
The `Baggage` document has a `version` field. When updating, the query matches `{ _id, version }` and increments `version`. If another scan updated the bag simultaneously, the update fails cleanly with a conflict error.

Part 5: Security & Authentication

17. How are user passwords hashed?
Using `bcryptjs` with 12 computational rounds. Plaintext passwords are never stored in memory or persisted to the database.
18. How are user enumeration attacks prevented on login?
If an entered email does not exist, the server executes a dummy comparison against `DUMMY_HASH`, ensuring response timing is identical whether or not an account exists.
19. Why use server-side sessions instead of JWT in localStorage?
JWTs in localStorage are vulnerable to XSS theft. AeroTrack Pro uses `HttpOnly`, `SameSite=lax` signed cookie sessions stored in MongoDB, allowing immediate session revocation by administrators.
20. How is CSRF prevented with cookie authentication?
State-changing requests (`POST`, `PATCH`, `DELETE`) require the custom header `X-Requested-With: aerotrack`. Browsers forbid cross-origin sites from sending custom headers without CORS preflight authorization.

Part 6: Algorithms & Machine Learning

21. What is modulo bias, and how is it resolved?
Taking a 32-bit integer modulo 1,000,000 gives lower remainders a higher probability because $2^{32}$ is not divisible by 1,000,000. Rejection sampling rejects integers $\ge 4,294,000,000$, ensuring an exact uniform $10^{-6}$ probability.
22. How does the anomaly engine detect skipped checkpoints?
`checkTransition()` inspects the delta in the 8-stage main flow. If moving from `CHECKED_IN` (index 1) to `LOADED` (index 3), it returns `skipped: ['SECURITY_SCREENING']`, triggering a high-severity alert.
23. How does the delay-risk baseline heuristic calculate scores?
It extracts a 9-feature operational vector and applies additive heuristic weights (dwell ratio, missed checkpoints, departure proximity), bounding output risk in $[0.05, 1.0]$.
24. Why is logistic regression suitable for delay prediction?
Logistic regression produces linear log-odds where each factor's exact contribution can be explained to ground handlers in plain English, avoiding opaque black-box decisions.

Part 7: Deployment & Operations

25. What is the difference between deploying on Render vs Vercel?
Render runs a persistent container where background `setInterval` anomaly sweep timers and connection pools run continuously. Vercel runs serverless lambdas that freeze between requests.
26. What is CORS, and how is it configured?
Cross-Origin Resource Sharing restricts which browser origins can call the API. In `backend/src/app.js`, CORS strictly validates incoming origins against `CLIENT_URL` and `CORS_ORIGINS`.
